# W4 PRD: 게시글 검색과 태그 조합

## 문제와 대상

독자는 기억하는 제목이나 요약으로 글을 찾고 싶지만 현재 홈에는 태그 필터만 있다.
현재 Markdown 게시글 메타데이터를 재사용하여 별도 서버·비용 없이 검색을 제공한다.
사용자 인터뷰나 실제 사용량 분석으로 검증한 수요는 아니며 캡스톤의 제품 가설이다.

기능 성공은 자동화된 인수 조건 충족으로 판정한다. 검색 이용률, 탐색 시간 감소,
대규모 게시글 성능 및 실제 사용자 만족도는 이번 실행으로 확인할 수 없다.

## 사용자 스토리

- 독자로서 제목 일부 또는 요약 표현으로 원하는 글을 찾는다.
- 독자로서 AI 태그 안에서 검색하여 관련 글만 확인한다.
- 키보드 사용자로서 검색어 입력과 초기화 후 탐색을 계속한다.
- 결과가 없는 독자로서 안내와 초기화 버튼을 통해 목록으로 돌아간다.

## 기능 요구사항

- 홈의 기존 클라이언트 컴포넌트에 검색을 추가한다. 제목·요약·태그 중 하나에
  검색어 전체가 포함되면 일치한다. 여러 단어를 별도 토큰으로 분해하지 않는다.
- `trim().toLowerCase()`로 비교하며 정규식·HTML로 해석하지 않는다.
- 검색과 태그 조건은 AND다. 전체 태그를 누르면 태그만 해제하고 검색어는 유지한다.
- 검색 초기화는 검색어만 비우고 검색 입력에 포커스를 돌린다. 공백 입력도 초기화 가능하다.
- 결과 수는 `role=status`로 알리고, 태그 상태는 `aria-pressed`로 노출한다.
- 태그별 숫자는 전체 게시글 기준의 기존 의미를 유지한다.
- 입력은 현재 페이지에서만 유지되며 새로고침·상세 이동 후 복귀 시 복원을 보장하지 않는다.

## 비기능 요구사항

- 신규 의존성 없음. 기존 정적 생성·링크 탐색·태그 필터를 유지한다.
- 검색어를 URL, 저장소, 서버 검색 API, 분석 이벤트에 전송하거나 저장하지 않는다.
- 기존 Sentry의 에러 수집 설정을 유지하며 검색어를 별도 태그·컨텍스트에 넣지 않는다.
- 기존 스타일 변수와 반응형 컨테이너, 시맨틱 입력/버튼을 사용한다.
- 검색 연산은 게시글 수 N과 메타데이터 길이 L에 대해 대략 O(NL), 결과 배열 O(N)이다.
  실제 성능 개선을 주장하지 않으며 대규모 검색 인덱스는 도입하지 않는다.

## 비범위

본문 검색, 검색 URL 공유·영속화, 정렬 변경, 오타 교정, 초성 검색, 서버 검색,
사용자 계정, 유료 리뷰/관측 기능, 클라우드 배포, CI 보호 경로 변경은 제외한다.

## 구현·출시 순서

1. #5 기능, #6 검증, #7 운영 문서 이슈를 통합 PR에서 연결한다.
2. 검색 E2E의 실제 실패를 기록한 뒤 구현하고 전체 검증을 실행한다.
3. Hook 어댑터와 CodeRabbit 리뷰를 실행한다. 호스트 자동 Hook 호출과 수동 실행을 구분한다.
4. 검증·리뷰 결과와 한계를 PR에 남기고 병합한다. PR 병합 사실은 GitHub 상태로 확인한다.
5. 실패 시 배포를 진행하지 않는다. 병합 뒤 회귀가 발견되면 새 수정/되돌림 PR로 대응한다.
